# Agent Instructions — Travel Planning App

## Mission
Build the Travel Planning App incrementally from the approved product requirements, using the Texas trip as the first end-to-end validation scenario.

## Rules
1. Read the PRD and architecture documents before implementing features.
2. Do not silently expand product scope.
3. Keep `main` stable; make changes through focused branches and pull requests.
4. Prefer small, testable changes over large rewrites.
5. Never commit secrets, API keys, service-role keys, passwords, or production credentials.
6. Document material architecture and schema decisions.
7. Treat the Texas trip as test data/scenario, not hard-coded product logic.
8. Flag uncertain product decisions for owner review rather than inventing requirements.

## Planned Stack
- GitHub — source control and project history
- Vercel — web application deployment
- Supabase — database/auth/backend services
- Vapi — voice capabilities where appropriate
- VPS — optional services that need persistent/custom infrastructure

Exact framework and service boundaries should be finalized during implementation setup.
